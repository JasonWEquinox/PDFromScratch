## SDK readiness

- **Stable and current.** ModelContextProtocol and ModelContextProtocol.AspNetCore have been GA since 1.x and are at 2.4.0 (2026-11-07) (F1, F2). The 2.x line implements spec 2026-07-28 (F3). It can also serve 2025-11-25 clients on the same endpoint through `HttpServerSessionMode` (F5), which matters because clients will adopt the new revision at different speeds.
- **Transports.** stdio and Streamable HTTP are the main ones. HTTP is stateless by default in 2.x, which suits horizontally scaled containers. SSE is legacy: it is opt-in only (F6), and Claude Code calls it deprecated (F20).
- **Auth.** Auth is built in: JWT bearer plus `AddMcp` for RFC 9728 resource metadata, plus `RequireAuthorization` (F9, F10). It plugs into Entra ID or any OIDC provider through standard ASP.NET Core auth. Recent security patches (F7, F8) mean we should pin to 2.4.x or later and track patch releases.
- **Risks.** The release cadence is fast and includes breaking changes within 2.x (F4, F6), so plan for small upgrades every month or two. Skills support is experimental (F8). I could not confirm the official samples list or spec details first-hand (fetches were blocked).

## Retrieval recommendation inputs

- **Baseline: BM25.** The evidence shows BM25 is a hard baseline to beat for code and docs (F18, F19), and hybrid fusion without a reranker gives modest or no gains (F17, F18). This supports starting with lexical search only. SQLite FTS5 via Microsoft.Data.Sqlite is the obvious in-process option, but I did not verify its bm25() support or the FTS5 build flags in this run (see Leads).
- **Hybrid later, if needed.** Hybrid with a reranker gave the best quality in F17. If we add vectors, use stable components:
  - Postgres + pgvector via CommunityToolkit.VectorData.PgVector 1.0.2 (stable, F12) for a shared server.
  - sqlite-vec via CommunityToolkit.VectorData.SqliteVec (preview, alpha native extension, F13) is acceptable for local or per-developer use but is a risk on a server.
  - Avoid the deprecated Microsoft.SemanticKernel.Connectors.* packages (F11).
- **Local embeddings keep docs on our network.** ElBruno.LocalEmbeddings (F15) runs ONNX inference offline and implements the Microsoft.Extensions.AI interface. It is maintained by one person, so wrap it behind `IEmbeddingGenerator` to keep it swappable. Model files download once from Hugging Face, so mirror them internally if outbound access is restricted.
- **Abstractions.** Microsoft.Extensions.VectorData plus Microsoft.Extensions.AI keep the store and the embedder swappable (F12, F14, F15).
