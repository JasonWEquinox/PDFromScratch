## WolverineFx case

- **What exists:** The Wolverine docs (VitePress) build with `vitepress-plugin-llms` (F10). That plugin emits `/llms.txt`, `/llms-full.txt` and a per-page `.md` for each page (F7), so all three are expected under the docs host. The URLs to try are:
  - `https://wolverinefx.io/llms.txt`
  - `https://www.wolverinefx.io/llms-full.txt` (the link in the docs nav)
  - per-page Markdown, e.g. `https://wolverinefx.io/guide/<page>.md` (inferred from plugin behaviour; not verified)
- **Marten (sibling):** Same setup, with `https://martendb.io/llms-full.txt` (F11). JasperFx/jasperfx and weasel only matched "llms" in package.json or lockfiles. I did not check whether they publish their own docs sites.
- **Format:** Markdown in llmstxt.org shape: an index file plus one concatenated full file. Wolverine docs inline code samples with mdsnippets (`docs:build` runs concurrently with the mdsnippets group), so llms-full.txt should contain real compiled C# samples. That makes it a good fit for code-snippet extraction (inferred).
- **Size and update cadence:** Not verified, because the proxy blocked the docs hosts. The files are regenerated on every docs build, so cadence follows docs deploys from `main`. No Last-Modified header was available.
- **Not found:** A Wolverine Context7 `context7.json`, an official Wolverine MCP server, or agent skills. The `/guide/ai` page is about the `WolverineFx.AI` runtime feature, not agent-facing docs (F12).
- **Implications:** (a) For Critter Stack libraries, ingesting `llms-full.txt` (or the per-page `.md` files listed in `llms.txt`) is the cheapest route to high-quality data, with no HTML crawl needed. (b) llms-full.txt has no version: it describes the latest docs only. For per-version docs, fall back to the Git repo `docs/` folder at a release tag (F14, F16). (c) There is a host inconsistency between www and apex (F10), so follow redirects and normalise URLs when deduplicating.

## Recommended ingestion design inputs

1. **MVP source types, in priority order:**
   - (i) **llms.txt and llms-full.txt / per-page .md**, for public libraries and vendor "for-AI" Markdown (F1, F2, F7, F10, F11). Prefer the per-page .md listed in llms.txt over the monolithic full file, because it keeps page boundaries and URLs for citation.
   - (ii) **Git repo docs folders** (Markdown/MDX plus README), for public and private libraries. Use Context7-style include/exclude config: folders, excludeFolders, excludeFiles, and default excludes for CHANGELOG, LICENSE, archive and i18n folders (F14). Clone locally so private content stays on the network.
   - (iii) **Website crawl**, as a fallback only (F16).
   - (iv) **.NET XML doc comments**: there is no llms.txt route via DocFX (F9). Generate from the compiled `*.xml` doc files that ship with NuGet packages, or from `docfx metadata` YAML. This is a custom adapter (gap).
2. **Private repos:** Resolve tokens with explicit config first, then environment variables (F18). Fail loudly on 401/403/404-with-empty-body instead of silently falling back to anonymous (F18 pitfalls). Plan GitLab and Azure DevOps PAT adapters yourself; no evidence of them existed in the tools reviewed. Context7 gates private sources behind Pro/Enterprise on its SaaS, and its backend is closed source (F13, F15), so private ingestion must be self-hosted.
3. **Chunking:** Split by heading and keep the heading path as metadata. Merge small neighbours, but never across an H1/H2 boundary (F17). Keep fenced code blocks atomic and index them as separate "snippet" records with language and title or description, so they can be ranked by language as Context7's `language` parameter does (F13). Use a Tree-sitter-style declaration path for source and API files (F17). Rebuild context around a hit from parent and sibling chunks (F17).
4. **Versioning:** Use a library-plus-version key. Versions come from Git tags or branches (`previousVersions` with tag or branch, F14) and are stored separately (F16). The llms.txt path supports "latest" only.
5. **Refresh:** Combine scheduled re-crawls (Context7 schedules by popularity) with push-triggered refresh: a webhook, or a CI action on push to the default branch (F15). Provide an in-place `refresh` and a `--replace` for each version (F16). Use content hashing or ETag to skip unchanged pages (inferred; not evidenced in this run).
6. **Token-budgeted responses:** Context7 URLs in search results take a `?tokens=10000` parameter (seen in search-result URLs, e.g. `context7.com/dotnet/docfx/llms.txt?tokens=10000`). Expose a `tokens` (budget) parameter on the docs tool and fill it with ranked snippets first, then prose. I could not read Context7's own docs on this parameter (blocked).
7. **Library rules:** Consider a per-library `rules` field (agent guidance), screened for prompt-injection content as Context7 does (F14). This matters for vendor-published "for-AI" docs, which are untrusted input.
